# 开发计划（PLAN）

最后更新：2026-11-09　状态：v1（待评审）
维护规则：**本文件是项目优先级的唯一来源**。`HANDOFF.md §8` 的旧 TODO 列表已作废，只保留为历史。

---

## 1. 定位：这个项目同时是三件事

| 角色 | 重要性 | 对它的要求 |
| --- | --- | --- |
| **自用工具**（主） | 最高 | 可靠、可信、改资料后不用等很久。宁可少功能，不能给错答案 |
| **开源项目**（后续） | 中 | 别人 clone 下来三条命令能跑；没有 Ollama 也能用离线模式看效果 |
| **简历项目**（附带） | 中 | 每个技术选择都能被追问三层；有可复现的数字对比 |

推论（这条会约束后面所有决策）：
- 自用要求 → **可信优先于聪明**。引用校验、拒答、增量索引比 rerank/Web/画像重要。
- 简历要求 → **数字可复现优先于数字好看**。评测集必须真实、必须冻结。
- 开源要求 → **零依赖是可讲的卖点**，不要为了一个可选功能把核心拖进 onnxruntime。
  可选能力走「可选依赖 + 配置开关」，见 `adr/0001-single-codebase.md`。

## 2. 成功标准（Definition of Done）

按顺序达成，前一条不满足不进入下一条：

1. **自用可用**：改一份资料后 `ingest` 30 秒内完成（增量）；任意答案的出处能定位到原文行区间；
   问库里没有的问题，10 次里至少 8 次明确拒答。
2. **可信可核对**：答案里的每个 `[n]` 都能在本次召回的来源里找到，且被引片段确实包含该结论；
   非法引用（编号越界、指向空片段）**程序可检出**，不依赖模型自觉。
3. **数字可信**：语料 ≥ 40 个有效片段、评测 ≥ 25 题（其中 ≥ 6 题是负样本）；
   README 里的 Recall@5 明显小于 1.00，否则公开说明「语料不足，指标饱和」。
4. **能讲清楚**：`docs/adr/` 至少 5 条决策，每条写清选项、代价、什么条件下推翻。

## 3. 里程碑

依赖顺序排列。**「验收」一栏必须是可执行的命令或可数的数字**，否则这个里程碑没做完。

| ID | 里程碑 | 内容 | 产出物 | 验收 | 预算 |
| --- | --- | --- | --- | --- | --- |
| M0 | 真实语料与基线 | 6–7 份真实资料入库；按 `EVAL.md` 重写评测集（25 题 + 6–8 负样本） | `data/eval/questions.jsonl`、`docs/baselines/2026-11-baseline.md` | 有效片段 ≥ 40；`python -m kb.eval --md` 与 `python -m kb.eval_answer` 都能跑出数 | 1.5 天 |
| M1 | 回归安全网 | pytest：切分/合并/BM25/RRF/脱敏/拒绝清单/引用解析 | `tests/`、`pytest.ini` | `python -m pytest -q` 全绿，≥ 25 个用例；同一输入两次 ingest 产出的 `chunks.jsonl` 字节一致 | 1 天 |
| M2 | 可信答案 | 引用编号合法性校验 + 引用支撑性检查 + 拒答策略；答案级评测脚本 | `kb/cite.py`、`kb/eval_answer.py` | 引用合法率 100%；负样本拒答 ≥ 8/10（`eval_answer` 输出）；正样本答案不因校验被误删 | 2 天 |
| M3 | 出处精确 | `Chunk` 记 `start_line`/`end_line`；合并片段保留行区间 | `kb/chunk.py`、`kb/store.py` | 抽 20 条答案，出处行区间 100% 能从原文核对；`chunks.jsonl` 字段有 `end_line` | 1 天 |
| M4 | 增量索引 | `index/manifest.json` 记 `path/sha256/mtime/chunk_ids`；只重算变化文件；删文件要清理 | `kb/store.py`、`kb/ingest.py` | 改 1 份文档增量耗时 < 全量 1/3；删除文档后索引条数正确；改回内容后索引与原索引一致 | 1.5 天 |
| M5 | rerank 可插拔 | `rerank(query, hits, n)` 接口 + `off`/`llm`/`onnx` 三种实现 | `kb/rerank.py`、`requirements-optional.txt` | 在 M0 基线上 Recall@5 或 MRR 有提升且延迟 ≤ 2 秒；无提升就默认 `off` 并如实写进基线表 | 2 天 |
| M6 | Web/API | FastAPI + 单页：输入框、流式答案、可点击出处、拒答展示 | `kb/web.py`、`web/index.html` | 本机 8000 端口可用；点出处能定位到片段原文；不引入前端框架 | 2 天 |
| M7 | 分层路由 | `L0`→云端、`L1`→本地，**分索引**，云端只看到 L0 片段 | `kb/backends.py`、双索引 | L1 文本不进入发往云端的 payload（有测试断言）；L0 问题走云端且答案带出处 | 2 天 |
| M8 | 结构化画像 | 技能表/项目表/时间线，支撑跨文档问题 | `kb/profile.py` | 10 个跨文档问题里 ≥ 7 个能答对且带出处 | 后话 |

**先后顺序的理由**：M0 不做，后面所有「优化有效」都不可证伪（现在 6 片段 / `TOP_K=5`，
每次查询返回 83% 的库，指标必然满格）；M1 不做，M3/M4 会反复改坏；M2/M3 是「自用可信」的核心；
M4 是自用体验的分水岭；rerank/Web/画像都很诱人，但都不解决「会不会给错答案」。

## 4. 明确不做（non-goals）

写清楚不做什么，比列一堆想做的更能防止范围膨胀。

- 多用户、账号、权限：单机单人，不做。
- 向量数据库 / Faiss：片段数 < 5000 之前不上，理由与推翻条件写进 `adr/0006`。
- 云端 embedding：`L1` 永不，`L0` 也不做，收益抵不上隐私叙事（见 `adr/0007`）。
- 移动端、Electron、聊天历史、多轮对话：不做，`ask` 保持单轮。
- 自动爬取/同步外部资料：不做，只处理手工放进 `data/raw` 的文件。
- 微调模型：不做。

## 5. 风险与缓解

| 风险 | 触发信号 | 缓解 |
| --- | --- | --- |
| 语料不够，指标仍饱和 | M0 后 Recall@5 = 1.00 | 优先增加长文档（课程 PDF、笔记）；再不行只报 Recall@1/@3 并在 README 写明限制 |
| 真实资料含隐私，误入库 | `chunks.jsonl` 里出现真实手机号/证件 | 入库前脱敏已有；新增「入库后自查」：grep 手机号/身份证正则，命中即失败 |
| 拒答过头，正常问题也拒 | M2 后负样本拒答率高但正样本答案变短 | 同时监控正样本「拒答率」，> 10% 就回退阈值 |
| 双版本维护负担 | 出现「自用版好、简历版坏」 | 已决策：单库 + 依赖分层（`adr/0001`） |
| 范围膨胀 | 里程碑里出现两个以上新能力 | 一个里程碑只允许一个「新能力」新增 |

## 6. 工作方式（补上「计划先行」的机制）

用户对「先写代码再补计划」不满意，这一节是防止它再发生的机制，不是口号：

1. **每个里程碑开始前**写 `docs/spec/Mx-*.md`，一页，四段：目标 / 输入输出 / 验收命令 / 不做什么。
   验收命令写不出来的里程碑，不许开工。
2. **每个里程碑结束后**写 `docs/baselines/` 下一篇记录：改动、前后数字、结论（保留还是回滚）。
3. **架构级选择**（新增依赖、改存储格式、改融合策略）先提 ADR，状态 `Proposed` → 用户确认 → `Accepted`。
4. **每周 15 分钟复盘**：只回答三件事——上个里程碑做完了吗、验收数字对不对、下周砍掉什么。
5. 改检索策略前先跑基线，这条沿用 `HANDOFF.md §10`，已固化为 `EVAL.md` 的纪律。

## 7. 时间预算

按 M0→M4 约 7 个工作日，可得到「自用可信 + 简历可讲」的最小完整版本；
M5–M6 视面试准备情况插入（M5 性价比最低，可最先砍）。

如果 11 月底前后需要开始投递：**砍 M5、M6，把 M0–M4 做扎实**。
一个「评测可信、引用可核对、增量索引」的 CLI，比一个「有网页、指标虚高」的项目好讲得多。
