# ADR-0002：评测先于优化，且指标必须过「语料门槛」

- 状态：Accepted
- 日期：2026-11-09
- 关联：`docs/EVAL.md`、PLAN M0

## 背景

现状：4 份文档、6 个片段、`TOP_K=5`、6 道题，`Recall@5 = 1.00 / MRR = 1.00 / KW = 100%`。

每次查询返回全库 83% 的片段，所以这组数字是**算术结果**，不是检索能力：
改对改错都可能是 1.00。原有 TODO 把「扩评测集到 20–30 条」列为 P0，
但如果语料仍是 6 个片段，题量变大只会让饱和的 1.00 更稳定。

## 选项

- **A. 按原 TODO 先扩题量**：成本最低，但指标仍无区分度。
- **B. 先扩语料到达标，再扩题量**：需要真实资料 + 标注时间。
- **C. 只改指标口径**（加 `Recall@1/@3`、答案级指标、负样本）：不改语料。
- **D. B + C**：语料门槛 + 口径修正，双管齐下。

## 决策

选 **D**。

1. **语料门槛**：有效片段 ≥ 40、文档 ≥ 6、`TOP_K/片段数 ≤ 0.15`，
   不达标只能报 `Recall@1/@3`，并注明「@5 无区分度」。
2. **口径修正**：同时报 `Recall@1/3/5`、`MRR`、`KW 覆盖`、`NegFPR`；
   M2 起加答案级指标（引用合法率、支撑率、拒答率、误拒率）。
3. **声明政策**：`README` 里写 `Recall@5` 必须同时给出「片段数、k、题数」；
   语料未达标时，任何单个指标不许写成「提升」。
4. **噪声步长**：n 题时单题步长 `1/n`，变化小于一个步长不算改进
   （这就是 n=6 时 `MRR 0.76 → 1.00` 不能当证据的原因）。

## 后果

- 短期内指标会**下降**（例如 `Recall@5` 从 1.00 掉到 0.8x）。这是尺子有刻度的表现，不是退步。
- 需要人工标注约 25 题，含 6–8 条负样本，耗时半天到一天。
- 评测从「跑一下看个乐」变成一个有成本的流程，必须先冻结题集（sha256 记档）。

## 推翻条件

如果用户的真实语料**长期**到不了 40 个片段（例如 6–7 份短文档就是全部），
允许的替代方案是「合成干扰语料」：真实片段 + 公开课程笔记混合到 ≥ 40 片段，
专门测排序与抗噪；但必须在报告里写明「语料为合成，`expected_docs` 只标真实片段」。
**不接受的做法**：为了凑片段数把同一份文档切得更碎。
