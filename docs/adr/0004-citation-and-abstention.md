# ADR-0004：引用校验与拒答必须由代码保证，不能只靠 prompt

- 状态：Accepted
- 日期：2026-11-09
- 关联：PLAN M2、`kb/ask.py` 的 `PROMPT`

## 背景

项目的立身之本是「每条结论可核对」。现状是：`ask.py` 的 prompt 第 2/3 条要求模型带 `[编号]`、
找不到就说找不到，但**代码对输出不做任何校验**：

- 模型可以输出 `[6]`，而本次只召回了 5 条；
- 模型可以引对编号但说错内容；
- 模型可以整段没有引用，仍然输出结论。

也就是说，这个卖点目前由被约束者的自觉保证。这是最脆弱的一环。

## 选项

- **A. 继续只靠 prompt**：零成本，但不可证伪。
- **B. 输出结构化 + 后处理校验**：解析引用，越界/缺失时处理，必要时拒答。
- **C. 完整 NLI / 事实核验**：准确但要模型与标注，当前规模不划算。

## 决策

选 **B**，分三层，按成本从低到高：

1. **格式层（硬性）**：要求模型最后一行输出 `SOURCES: 1,3`，正文结论用 `[n]`。
   解析失败不算答案，走拒答分支。这比从自由文本里正则抽 `[n]` 稳定得多。
2. **合法性层（硬性）**：`n` 必须 ∈ `1..k` 且对应片段非空。
   不合法 → 该句剥离引用并标记 `[?]`；**全部引用非法 → 输出「资料中没有找到可核对的依据」**，
   不展示模型正文。
3. **支撑层（软性告警）**：用字符 bigram 重叠（零依赖）估计「被引片段是否覆盖该结论」，
   低于阈值只提示不计分、不删除；将来可换成 LLM 判定。
   注意：不追求完整 NLI，避免误杀。

拒答策略同时使用两个信号：
- **检索信号**：Top-1 的向量分与 BM25 分同时低 → 倾向拒答；
- **生成信号**：模型的 `SOURCES:` 为空或全非法。

阈值**从数据定**，不拍脑袋：M0 基线里分别记录正样本 / 负样本的 Top-1 分数分布，
取两者能分开的区间作为初值，再用 `eval_answer` 的拒答率/误拒率调。

## 后果

- 会有**误拒**。用 `eval_answer` 监控：负样本拒答率 ≥ 80%，正样本误拒率 ≤ 10%，任一不达标就回退。
- `ask.py` 的输出流程要重构：先拿全文 → 校验 → 再渲染，不能边流式边校验。
  折中：仍流式展示，但流结束后立即校验并追加/替换结论，明确标注哪些引用不可信。
- 引用合法率必须程序判定为 100%，这是 M2 的验收条件。

## 推翻条件

若连续 3 次评测中 prompt 已稳定给出「合法率 ≥ 98% 且支撑率 ≥ 95%」，
可以把合法性层从**拦截**降级为**告警**（只提示不替换答案），
把复杂度让给「支撑层」。但 `SOURCES:` 的格式要求保留——它为后续增量校验提供了稳定接口。
