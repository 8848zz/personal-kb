# 个人知识档案库

把散落的个人资料（简历、笔记、项目记录、课程 PDF）变成一个能问答的私有索引：
**只依据你的资料回答，每条结论都标出处，找不到就说找不到。**

## 为什么不是「把资料丢给大模型」

因为大模型会编，而且编得像真的。这个项目的核心不是「接入模型」，
而是**让每个答案都能被核对**：

- 每条结论带 `[编号]`，编号指向具体文件、章节、行号
- 检索用「向量 + BM25」混合，专有名词和语义相近都能召回
- 有一份带标注的评测集，改动检索策略前先看数字掉不掉

## 隐私设计

数据分三级，**不同级别走不同推理路径**：

| 级别 | 内容 | 处理 |
| --- | --- | --- |
| `L0` | 课程 PDF、公开资料、开源代码 | 可选云端模型 |
| `L1` | 简历、日记、项目记录 | **全本地**（Ollama embedding + 生成） |
| `L2` | 密码、证件号、银行卡 | **不入库**，交给密码管理器 |

两个关键点：

1. **embedding 也必须本地**。否则原文在建索引阶段就已经出机器了——
   生成放本地只是「最后一步没出去」。
2. `data/raw` 下文件名命中拒绝清单（密码/secret/身份证/银行卡等）会**直接跳过**，
   并在建索引时点名。
3. 入库前自动脱敏手机号、身份证号、银行卡号。

> 目前是「单机单层」实现：敏感层走 Ollama 本地模型。
> 要在同一进程里混用云端和本地，需要按 `tier` 分流——留给下一步。

## 快速开始

```bash
# 1. 准备本地模型（只做一次）
ollama pull bge-m3          # embedding，约 1.2 GB
ollama pull qwen2.5:7b      # 生成，8 GB 显存够用

# 2. 放资料
#    data/raw/L0/   公开资料
#    data/raw/L1/   个人资料（走本地）
#    支持 .md / .txt / .pdf（PDF 需 pip install pypdf）

# 3. 建索引（先用仓库自带的虚构样例跑通）
$env:KB_RAW="data/demo"    # 用真实资料时删掉这行，默认读 data/raw
python -m kb.ingest

# 4. 提问
python -m kb.ask "我简历上写了几个项目？"

# 5. 看检索质量
python -m kb.eval --md
```

没装 embedding 模型时可以用离线模式验证管道是否通畅
（检索质量会明显下降，因为用的是哈希向量）：

```bash
$env:KB_OFFLINE = "1"; python -m kb.ingest; python -m kb.eval
```

## 目录结构

```
kb/
  config.py     所有可调参数
  textio.py     读取 + 脱敏
  chunk.py      标题感知切分
  tokenize.py   中文二元组分词（零依赖）
  embed.py      Ollama embedding / 哈希兜底
  bm25.py       关键词排序
  store.py      索引落盘与加载
  retrieve.py   向量 + BM25 → RRF 融合
  ingest.py     建索引
  ask.py        问答
  eval.py       评测
data/
  demo/{L0,L1}/ 虚构样例，随仓库发布，供他人复现
  raw/{L0,L1}/  真实资料，**永不入库**（.gitignore）
  eval/         评测集（与 demo 配对）
  index/        索引产物（不进 git）
```

## 实验记录

改检索策略时，先跑 `python -m kb.eval --md`，把数字贴到这里再下结论。

| 版本 | 改动 | Recall@5 | MRR | KW 覆盖 |
| --- | --- | --- | --- | --- |
| v0 | 哈希向量（离线验证管道用） | 1.00 | 0.76 | 100% |
| v1 | bge-m3 向量 + BM25 → RRF | 1.00 | 1.00 | 100% |

**注意这份数字的说服力有限**：示例语料只有 4 个文件、6 条片段，
Recall@5 已经饱和，只能看出 MRR 有提升。真实评测需要
几十上百份文档和 20 条以上问题，否则指标会虚高——这一点写进来，
是因为面试官一定会问「你的评测集多大」。

## 已知缺陷

- 小片段合并进相邻片段后，出处里的标题和行号是**近似值**（保留了前一片段的）。
  引用精度要求高时需要改成按行号区间记录。
- PDF 只做了按页分隔，双栏排版会串行。
- 没有重排（rerank）阶段，Top-5 里仍可能有噪声。
- 分级路由尚未实现：敏感层（L1）走本地，公开层（L0）接云端模型的分流留给下一步。

## 开发计划与设计记录

这个项目先做了一版能跑的原型，之后才补的计划。补计划的目的是让「下一步做什么」「做到什么算完」
和「数字能不能信」有唯一答案：

- [`docs/PLAN.md`](docs/PLAN.md)：里程碑与验收标准（优先级只看这里）
- [`docs/EVAL.md`](docs/EVAL.md)：评测协议——语料门槛、指标口径、负样本、基线怎么记
- [`docs/adr/`](docs/adr/)：架构决策记录，每条都写了「什么条件下推翻它」

关于上面那张实验记录表：当前语料只有 6 个片段而 `TOP_K=5`，每次查询返回全库 83%，
所以 `Recall@5` 必然饱和。**在语料扩到 40 个有效片段之前，这张表只能看 MRR，不能看 Recall。**
